
# 🧪 EXPERIMENT 03 — Network Packet Sniffing and Credential Analysis Using Wireshark

---

## 🎯 Objective

To capture and analyze unencrypted network traffic using **Wireshark**, identify HTTP GET and POST requests, and examine plain-text data transmitted through an HTTP connection.

---

## 🧰 Tools / Requirements

* **Operating System:** Windows 10/11 or Kali Linux
* **Packet Analyzer:** Wireshark v4.x
* **Packet Capture Driver:** Npcap
* **Web Browser:** Google Chrome / Mozilla Firefox
* **Target Environment:** Acunetix Web Vulnerability Test Site
* **Protocol:** HTTP
* **HTTP Port:** TCP 80

---

## 📋 Experiment Scenario

Network packet sniffing involves capturing and analyzing data packets transmitted through a network interface.

Wireshark was used to monitor network traffic generated while accessing a web application that communicates using unencrypted HTTP.

Because HTTP traffic is not protected by TLS/SSL encryption, the contents of HTTP requests can be visible within captured packets.

The experiment focused on identifying:

* HTTP traffic
* HTTP GET requests
* HTTP POST requests
* Form-submission data
* Plain-text parameters transmitted through the HTTP request

---

## 🌐 Network Packet Sniffing

Wireshark uses packet-capture functionality provided by **Npcap** to capture network traffic through the system's network interface.

When HTTP is used over **TCP port 80**, the application-layer data is transmitted without HTTPS encryption.

Therefore, HTTP request contents can be examined in a packet capture.

---

# 📡 HTTP GET and POST Methods

## HTTP GET Method

The **GET** method is primarily used to request or retrieve resources from a web server.

Parameters associated with GET requests can be included within the URL.

In this experiment, captured GET requests were examined to identify the type of HTTP traffic generated while accessing the web application.

---

## HTTP POST Method

The **POST** method is commonly used when submitting form data to a web server.

In this experiment, the form submission was transmitted using an HTTP POST request.

The submitted form data was contained within the request payload.

Because the communication used unencrypted HTTP rather than HTTPS, the transmitted form parameters could be examined in plain text within the captured packet.

---

# ⚙️ Procedure

## Step 1 — Initialize Wireshark

Wireshark was launched on the system.

The active **Wi-Fi network interface** was selected to begin capturing live network traffic.

The selected interface was used to monitor packets generated during the web activity.

---

## Step 2 — Generate Network Traffic

The target web application was opened in a web browser.

The required form information was entered into the web page and submitted.

This generated HTTP network traffic that could subsequently be captured and analyzed by Wireshark.

---

## Step 3 — Filter HTTP Traffic

After generating the network traffic, the following display filter was applied:

```text id="v7k2p9"
http
```

This filter was used to isolate HTTP traffic from other background network traffic such as TCP, UDP, and DNS packets.

---

## Step 4 — Analyze HTTP GET Requests

The following Wireshark display filter was applied:

```text id="g1j8nx"
http.request.method == "GET"
```

This filter displays HTTP GET requests captured during the experiment.

The GET requests were examined to understand the HTTP requests generated by the web application.

GET requests primarily retrieved page components and did not contain the submitted form credentials in their payload.

---

## Step 5 — Analyze HTTP POST Requests

The following display filter was applied:

```text id="r5d3km"
http.request.method == "POST"
```

This filter isolated HTTP POST requests.

The packet containing the form submission was selected for further examination.

The Packet Details pane was expanded to inspect the HTTP form data.

---

## Step 6 — Examine the POST Payload

The HTTP POST packet was examined for the form data transmitted by the browser.

The **HTML Form URL Encoded** information was expanded in the Packet Details pane.

The transmitted form parameters could then be viewed because the communication was performed over unencrypted HTTP.

The captured fields included the username and password values submitted through the test form.

---

# 🛡️ Preventive Countermeasures

## 1. Use HTTPS

Web applications should use **HTTPS with TLS encryption** instead of unencrypted HTTP.

TLS encrypts the communication between the client and server, preventing captured network traffic from directly exposing the transmitted application data.

---

## 2. Implement HSTS

**HTTP Strict Transport Security (HSTS)** can be used to instruct browsers to communicate with a website using HTTPS.

This helps prevent browsers from being downgraded to unencrypted HTTP communication.

---

## 3. Network Isolation

Network-level controls can help restrict unauthorized packet capture.

Examples include:

* VLAN segmentation
* 802.1X authentication
* Network access controls

These measures can help restrict unauthorized access to local wired and wireless network traffic.
